Please review this task and create a brief implementation plan before making any code changes.

This is a lightweight planning task. Do not edit, create, delete, move, format, or refactor files until the short plan is complete.

The goal is to make a clean, focused change without over-planning, while still avoiding obvious mistakes, unrelated edits, or missed test coverage.

## Required Review

Before implementation, inspect the directly relevant files and confirm:

- Which file(s) need to change
- Which function, class, component, config, script, or test is affected
- What current behavior must be preserved
- Whether any nearby code depends on the current behavior
- Whether an existing test already covers this area

Do not search the entire repository unless the task clearly requires it. Follow direct imports or direct consumers only when needed.

## File Allow-List

Before coding, list the exact files expected to be touched.

For each file, include:

- Exact path
- Planned change
- Reason for the change

Do not modify files outside this list unless the plan is updated first.

Avoid unrelated cleanup, formatting-only changes, broad refactors, dependency changes, or opportunistic improvements.

## Simple Edge Case Check

Account for obvious edge cases relevant to the task, such as:

- Missing input
- Empty input
- Invalid value
- Bad path
- Existing behavior that should not change
- Basic backward compatibility concerns

Ignore theoretical edge cases that do not realistically apply.

## Implementation Plan

Provide a short step-by-step plan.

Each step should include:

- What will be changed
- Which file or symbol is involved
- How it will be verified

## Testing / Validation

Before coding, identify the checks that should be run.

Include:

- Existing tests to run, if any
- New test to add, if needed
- Manual verification step, if no automated test exists
- Expected pass condition

Use exact commands when known.

## Final Output Format

Return the plan using this structure:

1. Task summary
2. Files reviewed
3. File allow-list
4. Implementation steps
5. Basic edge cases
6. Tests or validation checks
7. Final pass/fail checklist

Keep the plan concise, practical, and focused. The goal is to prevent careless implementation mistakes without creating unnecessary planning overhead for a simple task.
